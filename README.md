# CueFlow

CueFlow describes message constraints in CUE and communication order as a server-local finite state machine. The compiler loads CUE through the official Go API and generates Rust or Python server/client state APIs.

## Download a release

Download the binary for your operating system and CPU from the [latest GitHub Release](https://github.com/jcfangc/cue-flow/releases/latest). Asset names use `cueflow-vX.Y.Z-<os>-<arch>`; Windows binaries end in `.exe`. The release also includes `SHA256SUMS` for checking the downloaded binary. A downloaded binary does not require Go or the CUE CLI to run.

For example, after downloading the Linux amd64 binary:

```sh
chmod +x ./cueflow-vX.Y.Z-linux-amd64
./cueflow-vX.Y.Z-linux-amd64 check --input ./path/to/cue-package
./cueflow-vX.Y.Z-linux-amd64 generate rust --input ./path/to/cue-package --output ./generated/cueflow.rs
./cueflow-vX.Y.Z-linux-amd64 generate python --input ./path/to/cue-package --output ./generated/cueflow.py
```

Replace `X.Y.Z` with the release version and the input path with a directory containing the user's CUE package. Windows users can invoke the matching `.exe` asset with the same subcommands and flags.

## Commands

Check a CUE package:

```sh
go run ./cmd/cueflow check --input ./cue/examples
```

Generate a Rust module:

```sh
go run ./cmd/cueflow generate rust --input ./cue/examples --output ./generated/cueflow.rs
```

Generate a Python module:

```sh
go run ./cmd/cueflow generate python --input ./cue/examples --output ./generated/cueflow.py
```

The `send` and `recv` transitions are interpreted from the server's point of view. The client API is generated by swapping those directions. Every nonterminal state exposes `close()` to send Close and `recv_close()` to wait for the peer's Close. A business receive method can also return `ReceiveOutcome::Closed`; transport failures remain `ProtocolError::Transport`. States with no business transitions are terminal.

Optional CUE fields are represented as `Option<T>`. The generated Serde deserializer accepts a missing field but rejects an explicit `null`, matching CUE's optional-field semantics.

The Python backend generates strict Pydantic v2 message models and separate server/client classes for each FSM state. State transitions return the next state type; mypy or another static type checker can reject calls that are unavailable in the current state. A session object is consumed at runtime when a transition is taken. Optional fields may be omitted and reject explicit `None`.

## First version limits

Both generators currently support object messages with string and boolean fields, plus bounded integer fields that fit `i64`. String validation supports non-empty constraints, CUE regular-expression patterns, and length bounds. Integer validation supports inclusive minimum and maximum bounds. A pattern that CUE accepts but the target regex engine cannot compile is reported during generated model initialization or validation. `cueflow check` validates protocol semantics independently of any language backend; unsupported CUE/JSON Schema constraints fail generation instead of being silently dropped.

Generated Rust code depends on Serde with its derive feature and the Rust `regex` crate. Generated Python code depends on Pydantic v2. Both backends define a transport boundary but do not implement networking, wire encoding, buffering, backpressure, or Runtime. The wire format remains open.

## Verification

Run the Go compiler checks and the CUE schema fixtures:

```sh
go test ./...
uv run --python 3.13 -- python scripts/test_schema.py
uv run --python 3.13 -- python scripts/test_compiler.py
uv run --python 3.13 --with 'pydantic>=2,<3' --with mypy -- python3 scripts/test_python.py
uv run --python 3.13 --with 'pydantic>=2,<3' -- python scripts/test_interop.py
```

`test_interop.py` launches one client and one server process per session over loopback TCP. It checks Query/Result cardinalities: 1:1, one Query to three Results, three Queries to one aggregate Result, and three correlated Queries to three Results. Each case runs Rust/Rust, Python/Python, and both cross-language directions. The N:1 and N:N cases use a `Finish` message to mark the end of the Query stream. Its JSON Lines framing is test-only; it does not define CueFlow's wire format.
